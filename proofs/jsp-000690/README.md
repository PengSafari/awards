# JSP-000690: a complete Lean formalization

This repository formalizes the **chromatic** interpretation of JSP-000690 / Erdős problem 834, using Ruiliang Li's known nine-vertex, twenty-two-edge hypergraph. It is a human-directed, AI-assisted formalization project by **PengSafari and OpenAI Codex**. The mathematical construction and original result remain credited to **Ruiliang Li**.

No new mathematical discovery or first-formalization priority is claimed. Other same-scope submissions already exist, including [awards PR 35](https://github.com/TheJustinSunPrize/awards/pull/35) and [PR 845](https://github.com/TheJustinSunPrize/awards/pull/845). Source availability and successful checks do not constitute organizer approval or an award decision.

## Complete statement

`Jsp690.jsp_000690`, in [Jsp690.lean](Jsp690.lean), proves the existence of a finite simple hypergraph that is:

- **3-uniform**: every edge contains exactly three distinct vertices;
- **3-chromatic-critical** for weak vertex colorings: it admits a proper three-coloring, admits no proper two-coloring, and every proper subhypergraph admits a proper two-coloring;
- of **minimum degree at least seven**.

`Jsp690.jsp_000690_nine_vertices` additionally proves that the witness has nine vertices, twenty-two distinct edges, and minimum degree exactly seven.

Weak coloring means that an edge is not monochromatic; its three vertices need not have pairwise distinct colors. Proper subhypergraphs may delete vertices, edges, or both, and need not be induced. This is the chromatic reading explicitly named in the prize catalog. The distinct transversal-critical reading is not the theorem formalized here.

## Mathematical source and statement correspondence

Ruiliang Li, *On an Erdős–Lovász problem: 3-critical 3-graphs of minimum degree 7*, [arXiv:2512.24850v1](https://arxiv.org/html/2512.24850v1), Theorem 1.2, Section 4, equation (5). See also [Erdős problem 834](https://www.erdosproblems.com/834).

| Mathematical object or assertion | Lean representation |
| --- | --- |
| Finite simple hypergraph | `Hypergraph V`, with finite vertex/edge sets and an endpoint-containment proof |
| Edges of size three | `Uniform H 3` |
| Degree of a vertex | `Degree H v`, counting distinct incident edges |
| Proper weak coloring | `ProperColoring H.edges c` |
| Three-chromatic-critical | `Critical3 H` |
| Arbitrary proper subhypergraph | `IsProperSubhypergraph G H` |
| Colorings on the actual retained vertices | `VertexColorable`, with `colorable_iff_vertexColorable` for positive palette sizes |

Paper vertices 1–9 are relabeled as `Fin 9` values 0–8. The edge list and the explicit three-coloring come from Li's paper. Our edge-deletion colorings were independently regenerated by exhaustive enumeration. The main construction theorem has **no hypotheses**.

## Proof organization

- [Jsp690/Basic.lean](Jsp690/Basic.lean) defines the objects and proves that, in a hypergraph without isolated vertices, every proper subhypergraph omits an edge. Single-edge deletion certificates then give colorings of all proper subhypergraphs, including those obtained by deleting vertices.
- [Jsp690/Witness.lean](Jsp690/Witness.lean) contains the explicit construction and coloring certificates.
- [Jsp690/Certificates.lean](Jsp690/Certificates.lean) uses kernel-checked `decide` to establish the finite facts. Non-two-colorability quantifies over every function `Fin 9 → Fin 2`, covering all 512 assignments.
- [Jsp690.lean](Jsp690.lean) assembles the full existence theorem, its quantitative strengthening, and the vertex-subtype version of criticality.
- [Audit.lean](Audit.lean) reports the transitive axiom dependencies of the main theorems and core lemmas.

There are no `sorry`/`admit` placeholders, added mathematical axioms, or native-evaluation proof shortcuts. The allowed foundational axioms are `propext`, `Classical.choice`, and `Quot.sound`.

## Reproduce

Install [elan](https://github.com/leanprover/elan), Python 3.9 or later, and Git. The checked-in `lean-toolchain` selects **Lean 4.30.0**. The manifest pins Mathlib to **c5ea00351c28e24afc9f0f84379aa41082b1188f** and records its transitive dependency commits.

From a checkout of this repository:

```sh
lake exe cache get Mathlib.Data.Fintype.Pi Mathlib.Data.Finset.Card
python3 scripts/verify.py --clean
```

The verification script rebuilds this project's modules, audits the six named theorem dependency closures, replays the imported environment with `leanchecker --fresh`, and runs the separate Python witness checker. It fails on an unexpected axiom or any failed command. Logs and a source-hash receipt are written to `verification/current/`.

The fresh replay uses the official Lean kernel, including imported constants. It is not an independently implemented type checker. The Python check is corroborating evidence, not a premise of any Lean theorem.

The [GitHub Actions workflow](.github/workflows/verify.yml) runs the same checks on Ubuntu and saves verification artifacts for 90 days. The [committed local evidence](verification/local/) comes from the submitter's machine; run outcomes are contributor-produced evidence, not independent human or organizer certification.
